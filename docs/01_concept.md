# コンセプト — Akamai-Origin Certificate Watcher

## 1. 一行コンセプト

> **Akamai 構成サイトの「Edge証明書」と「Origin証明書」の有効期限を自動で監視し、失効する前に気づける状態をつくる。**

---

## 2. 背景・課題

Akamai を経由する Web サイトでは、TLS 証明書が **2 系統** 存在する。

```
利用者 ──TLS①──▶ Akamai Edge ──TLS②──▶ Origin（自社/AWS等）
        Edge証明書              Origin証明書
```

- **Edge 証明書**: 利用者 ↔ Akamai 間。公開 FQDN に紐づく。
- **Origin 証明書**: Akamai ↔ Origin 間。Origin ホストに紐づく。

### よくある事故
- Origin 証明書の期限切れに気づかず、Akamai → Origin 間が突然エラーになる
- 監視が Edge（公開側）だけで、Origin 側が監視対象から漏れている
- 担当者・ベンダーが分散し、どの証明書が誰の管理かが追えない
- 手動の Excel 管理で更新漏れ・確認漏れが発生する

---

## 3. 目的

| 目的 | 説明 |
|------|------|
| **検出** | 期限切れ・期限接近・接続失敗を自動で検出する |
| **可視化** | サービス単位で Edge / Origin 双方の期限を一覧化する |
| **通知** | 危険なものだけを Teams に通知し、対応を促す |
| **証跡** | 検査履歴を蓄積し、いつ誰が何を確認したかを残す |

> **非ゴール（重要）**: 本ツールは **証明書を自動更新しない**。まずは「検出・監視・更新後の確認」に徹する。自動更新は事故時の影響が大きいため、対象外とする。

---

## 4. ターゲットユーザー

| ユーザー | 利用シーン |
|----------|-----------|
| インフラ / 運用チーム | 全社サイトの証明書期限を定期監視 |
| Web 担当者 | 自担当サービスの期限確認・更新後の検証 |
| 取引先ベンダー連携担当 | ベンダー管理分の期限把握 |

---

## 5. 提供価値

- **2 系統を1ツールで**: Edge と Origin を同じCSV定義から一括チェック
- **実行環境分離**: Origin は社内NW/AWS内、Edge は公開環境からと、到達可能な場所で分けて実行可能
- **止まらない監視**: 1対象の接続失敗で全体が止まらず、`ERROR` として記録
- **単一バイナリ**: Go製。Windows/Linux/macOS で動作、依存少なく導入が容易

---

## 7. ステータス定義

| ステータス | 条件 | 対応 |
|------------|------|------|
| `OK` | 残 31 日以上 | 不要 |
| `WARN` | 残 30 日以下 | HTML/CSV で確認 |
| `CRITICAL` | 残 14 日未満 | 通知・要対応 |
| `URGENT` | 残 7 日未満 | 通知・至急対応 |
| `EXPIRED` | 期限切れ | 通知・緊急対応 |
| `ERROR` | 接続不可・取得失敗 | 通知・到達経路・設定を確認 |

しきい値は CLI / API から変更可能。
